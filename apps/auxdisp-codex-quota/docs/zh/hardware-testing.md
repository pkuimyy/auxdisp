## 2026-11-11：0.1.1 发布前任务所有权修复验证

以下为真实 Windows / Python 3.13.7 上的本地修复验证记录，不代表最终 PyPI 发行包的安装验收：

- 原有任务通过修复后的 Bridge 只读查询；没有修改或删除原有任务。
- 125 项常规自动化测试通过，覆盖原生 Windows SID、本地用户名、带域用户名、不同用户、无法解析的身份及管理标记/动作拒绝路径。
- 显式启用的真实任务测试另有 1 项通过：程序注册唯一命名的临时任务，依次验证 `start`、`status`、重复 `start`、`stop`、`restart` 和 `uninstall-service`，均通过所有权校验，正常停止时没有使用强制终止。
- 临时任务使用合成账户，不调用真实 codex-auth；使用真实 COM、当前用户身份、Python 后台入口和跨进程 IPC。测试只清理本次创建的任务，并确认原任务查询结果保持不变。后台入口会使用正常用户诊断日志/状态目录，并可能向已连接屏幕输出合成内容。

真实任务测试默认跳过。需先安装待测代码，确认没有运行中的显示实例，再在 Windows 项目目录显式设置 `AUXDISP_CODEX_QUOTA_REAL_TASK_TEST=1`，运行 `pytest tests/test_scheduler_ownership.py::test_real_registered_task_lifecycle_preserves_existing_task`。它会注册并清理真实临时任务，不能当成无副作用的离线测试。

最终常规回归结果为 125 项通过、1 项真实任务测试默认跳过；该项已另行显式运行并通过。本机 Python 3.12 尝试中，两项现有 COM 检查因启动 PowerShell 子进程被拒绝（WinError 5）失败，因此完整回归和真实任务验收采用 Python 3.13.7，不声称 Python 3.12 本轮已完整通过。

上面的 PyPI 0.1.0 前台测试未注册真实任务；后续本地修复已完成临时任务注册和启停验收，但未验证关闭终端后常驻、重新登录自启、休眠恢复、电池行为、真实崩溃重试、长期运行或此 PyPI 版本的实体 USB 拔插恢复。修复发布后仍需验证最终发行包；后台生命周期的模拟测试不能替代系统级检查。
